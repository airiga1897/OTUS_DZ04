# Выполнение задания и результаты проверки

## Развёрнутая инфраструктура

Terraform разворачивает пять виртуальных машин Selectel:

| Узлы | Назначение | Настройка Ansible |
| --- | --- | --- |
| nginx1, nginx2 | Фронты и балансировка запросов к приложению | Nginx, upstream двух backend, кеш статики |
| backend1, backend2 | Веб-приложение и общее хранилище | Django, uWSGI, DRBD, GFS2, Corosync, Pacemaker |
| db | Некластеризованная БД и арбитр кворума | PostgreSQL, qnetd |

Перед фронтами используется облачный балансировщик Octavia HA.
Каждый Nginx передаёт запросы обоим backend по протоколу uwsgi.
Статика и media размещены на GFS2 в /srv/otus на обоих backend.
uWSGI обслуживает файлы с общего тома; дополнительные HTTP-сервисы
на backend не используются.

Вместо указанного в условии Yandex Cloud используется Selectel.
Роль облачного балансировщика выполняет Octavia; Keepalived не разворачивается.
Это отличие реализации от облачного варианта, указанного в задании.

## Проверки работы системы

| Проверка | Результат |
| --- | --- |
| Развёртывание Terraform и Ansible | Успешно |
| Миграции PostgreSQL и запуск Django/uWSGI | Успешно |
| Запись файлов каждым backend и чтение с обоих узлов | Успешно |
| Состояние реплик DRBD | UpToDate/UpToDate |
| Динамические страницы и readiness через оба Nginx | Доступны |
| Статика с новым ключом кеша через оба Nginx | Доступна |
| Повтор site.yml | changed=0, failed=0, unreachable=0 на всех пяти ВМ |

Проверка общего тома выполняет запись файлов с fsync на каждом backend
и взаимное чтение. Таким образом проверяется доступ к GFS2, а не только
наличие каталога или ответ из кеша фронта.

## Проверки отказоустойчивости

| Сценарий | Проверенное поведение | Результат |
| --- | --- | --- |
| Отключение backend1 | Динамика, readiness и статика обслуживаются оставшимся backend | Пройдено |
| Отключение backend2 | Динамика, readiness и статика обслуживаются оставшимся backend | Пройдено |
| Отключение nginx1 | Сайт обслуживается через nginx2 | Пройдено |
| Отключение nginx2 | Сайт обслуживается через nginx1 | Пройдено |
| Разделение сети backend | backend2 выключен через fencing, backend1 продолжает обслуживать сайт | Пройдено |
| Восстановление после каждого отказа | Реплики синхронизированы, GFS2 доступна, HTTP-проверки проходят | Пройдено |

До инициализации общего хранилища fencing проверен в обе стороны.
Отключение подтверждено независимым Nova API по SHUTOFF и power_state=4;
оба узла восстановлены.

После испытаний ресурсы стенда удалены. Проверка Terraform state
подтвердила отсутствие управляемых ресурсов.

Результаты без журналов и секретов приведены в
[verification-results.json](verification-results.json).
Порядок воспроизведения проверок — в [testing.md](testing.md).

## Границы решения

DRBD 9 dual-primary + GFS2 используется как неподдерживаемый учебный эксперимент.
Проверенные сценарии не доказывают безопасность всех возможных отказов.
Промышленная альтернатива — отказоустойчивое общее блочное хранилище
с резервируемыми iSCSI-контроллерами и несколькими путями доступа.

PostgreSQL некластеризован по условию задания. БД и облачный роутер остаются
отдельными точками отказа; размещение в одном сегменте не защищает от отказа зоны.

Описание архитектуры и причин выбора компонентов приведено в
[architecture-review.md](architecture-review.md).
